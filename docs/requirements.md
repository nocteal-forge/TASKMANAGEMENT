## 1. 確定事項(概要)

- 【確定】個人用の Web アプリとして開発する
- 【確定】日常・学習・仕事のタスク管理に使用する
- 【確定】タスクは「今日」「明日」「今週」「完了」の 4 つの分類に振り分ける
- 【確定】PC ではドラッグ&ドロップで、タスクを分類間で移動できる(スマホは長押しメニュー。)
- 【確定】システムは「フロントエンド(画面)」「バックエンド(API)」「データベース」の 3 階層で構成し、データは API 経由でデータベースに保存する([tech-stack.md](tech-stack.md) 2 章)
- 【確定】無料のホスティングサービスなどでインターネットに公開し、PC・スマートフォンから URL で使える([tech-stack.md](tech-stack.md) 3 章)

## 2. 背景・目的

- 【確定】背景: 日常・学習・仕事のタスクを、自分で管理するための個人用 Web アプリ。RaiseTech 初級編の学習の一環として、要件定義、設計、実装、公開までを通して取り組む
- 【確定】目的: 個人の日常・学習・仕事のタスクを、4 つの分類で管理する
- 【確定】ゴール(完成の基準): 初回公開時点で、これまで確定した機能をすべて実装し、公開 URL から利用できる状態を完成とする。対象は次のとおり
  - ログイン機能
  - 4 分類のタスク管理
  - 追加・編集・削除
  - PC のドラッグ&ドロップ
  - スマホの長押しによる分類移動と、編集モードでの並び替え
  - サーバーへの保存
  - ダークモード
  - 期限切れ表示
  - Mac・iPhone の Safari への対応

### 開発方針・学習目標

- 【確定】開発は一度に進めず、小さな機能単位に分割して、実装・検証する方針とする
- 【確定】GitHub の運用(Issue・ブランチ・PR)は、必須ではなく、できる範囲で活用する方針とする
  - 可能な範囲で、機能ごとに Issue を作成する
  - 作業ブランチを利用する
  - 可能な範囲で PR を作成し、変更内容を確認する
  - 学習や開発の進行に支障が出る場合は、無理に適用しない
  - GitHub 運用の実施状況は、アプリの完成条件には含めない

## 5. 非機能要件

### 対応ブラウザ

- 【確定】動作対象は次のブラウザに限定する
  - PC: macOS 版 Safari
  - スマートフォン: iOS 版 Safari
- 【確定】Chrome・Edge・Firefox・Android のブラウザは、今回の動作保証対象外とする
- 【確定】開発・動作確認の範囲を絞り、Mac と iPhone の Safari で正常に利用できることを優先する
- 【確定】対象バージョンは、macOS 版・iOS 版ともに Safari の最新版と、その 1 つ前のメジャーバージョン。現時点では、具体的な OS・Safari のバージョンは記録しない。実機で動作確認を行う段階で、使用する Mac と iPhone の OS・Safari のバージョンを確認し、必要に応じて記録する

### 性能

- 【確定】現時点では具体的な数値目標(応答時間、データ件数など)は設定しない
- 【確定】基本的な品質目標は次のとおり
  - タスクの追加・編集・削除がスムーズに反映されること
  - 分類間の移動や同一分類内の並び替えで、明らかな遅延やカクつきが発生しないこと
  - Mac・iPhone の Safari で、通常利用時にストレスを感じない操作性を確保すること
- 【確定】実際に使用して動作が重いと感じた場合は、必要に応じて性能改善を検討する

### データ保存

- 【確定】データに変更が発生する操作のたびに、即時に保存する。追加・移動・並び替えは、操作の直後に画面へ反映し、保存はバックグラウンドで行う。編集ダイアログの保存・削除は、ボタンを押したときに保存する
- 【確定】保存処理が失敗した場合に、ユーザーが変更内容を失ったと気づかない状態を避ける
- 【確定】保存先は、API 経由のデータベース([tech-stack.md](tech-stack.md) 2 章)

### 保存・通信エラー時の表示

詳細は [screen-requirements.md](screen-requirements.md) 5 章で確定済み。要約は次のとおり。

- 【確定】追加・移動・並び替えの保存に失敗したときは、画面を変更前の状態に戻し、画面下に赤系のエラー通知(「保存できませんでした。変更を元に戻しました。もう一度お試しください。」)を、ユーザーが閉じるまで表示する。再試行ボタンは設けず、同じ操作をやり直す
- 【確定】編集ダイアログの保存・削除は、ボタンを無効化して二重送信を防ぎ、「保存中…」「削除中…」と表示する。成功したらダイアログを閉じる。失敗したら、ダイアログを開いたまま入力内容を保持し、ダイアログ内に赤字でエラー(保存:「保存できませんでした。もう一度お試しください。」/ 削除:「削除できませんでした。もう一度お試しください。」)を表示する。再度ボタンを押せば、再試行できる
- 【確定】画面を開いたときは、ヘッダーと 4 つの分類の見出しを表示し、件数は「-」、各分類には薄いグレーの「読み込み中…」を表示する。読み込みに失敗したときは、ヘッダー直下に「タスクを読み込めませんでした。」と「再読み込み」ボタンを表示し、成功するまで追加・編集の部品は表示しない
- 【確定】ログインの通信エラー、ログアウトの失敗時の表示も、[screen-requirements.md](screen-requirements.md) 5.5 のとおり
- 【確定】他の端末との食い違い(競合)を検知したときの扱いは、[tech-stack.md](tech-stack.md) 3 章と [screen-requirements.md](screen-requirements.md) 5.7 のとおり

### セキュリティ(基本対策)

認証まわり(パスワードのハッシュ化、HTTPS 通信、総当たり攻撃への対策、API への認証適用)は、[tech-stack.md](tech-stack.md) 4 章で確定済み。そのほかの基本対策は次のとおり。

- 【確定】入力値の検証をサーバー側でも行う(文字数、必須、category の値など、全項目を対象とする。フロントエンドの検証だけに頼らない)
- 【確定】XSS 対策: タイトルやメモに悪意のあるスクリプトが入っても、画面で実行されないようにする。画面に出すときは、文字として扱う
- 【確定】ログインユーザーごとのデータ分離: API は、ログイン中のユーザーのタスクだけを返し、操作できるようにする(1 人でも、user_id で絞る)
- 【確定】秘密情報の管理: パスワード、データベースの接続情報などは、ソースコードやリポジトリに入れず、サーバー側の設定として持つ。リポジトリへの混入を防ぐ
- 【確定】セキュリティヘッダーの設定を行う
- 【確定】CSRF 対策(別のサイトから、ログイン中のユーザーになりすまして操作されることを防ぐ)を行う

### バックアップ

- 【確定】バックアップは、利用するサービスで可能な範囲で実施する方針とする
  - データベースサービスにバックアップ機能があれば、有効化する
  - 自動バックアップ機能がない場合は、大きな変更の前などに、手動でバックアップする
- 【確定】バックアップの実施は、アプリの完成条件には含めない

### サーバーの稼働

- 【確定】サーバーの稼働率について、数値目標は設けず、無料サービスの範囲で運用する
- 【確定】サーバー停止時は、読み込み失敗の表示([screen-requirements.md](screen-requirements.md) 5.5)を表示する
- 【確定】無料サービスの休止から起動するまでの待ち時間は、許容する
- 【確定】稼働率の目標は、アプリの完成条件には含めない

### テスト方針

- 【確定】重要な部分は自動テストを実施する。対象は次のとおり
  - 並び順の振り直し
  - 入力値の検証
  - ログインの判定
  - ログインユーザー以外のデータにアクセスできない制御
- 【確定】画面操作(ドラッグ&ドロップ、長押しなど)は、Mac と iPhone の Safari で手動確認する
- 【確定】自動テストは、実装する機能に合わせて、小さな単位で追加していく。上記 4 つは、引き続き自動テストの対象とする

### その他

- 【確定】初期リリースでは、画面の言語は日本語のみとする。画面表示、ボタン名、通知、エラーメッセージなど、すべて日本語に統一する。端末の言語設定による自動切り替えは行わない。将来的な多言語対応は、必要になった段階で検討する
- 【確定】アクセシビリティ: 初期リリースでは、基本的な対応を目標とする
  - 標準的なボタン・入力欄を使用する
  - 文字と背景のコントラストを十分に確保する(ライト・ダークの両方)
  - ボタンや入力欄に、適切な名前を設定する
  - iPhone の VoiceOver で、ログイン・タスク一覧の確認・追加・編集・削除ができることを目標とする
  - ドラッグ&ドロップや長押しなどの特殊な操作は、VoiceOver での対応を必須としない
  - すでに確定している、タップ領域約 44px 以上(カードの最低高さ)、色だけに頼らない情報伝達(期限切れの「!」)の方針を維持する

## 7. 旧版から削除・格下げした内容

- ラベル、チェックリスト、検索・フィルタ、アーカイブ → 未指定のため削除(将来対応するかは未決定)

## 9. 用語集

| 用語 | 意味 |
| --- | --- |
| 分類 | 「今日」「明日」「今週」「完了」の 4 つ。タスクは必ず 1 つの分類に属する |
| 列 | PC の横並び表示での、1 つの分類のまとまり |
| カード | 一覧に表示される、タスク 1 件の表示 |
| 編集ダイアログ | カードをクリック/タップすると開く、タイトル・メモ・期限日を変更し、削除もできる画面 |
| 編集モード | スマホで、同じ分類内の並び替えだけを行うモード(「編集」ボタンで入る) |
| 配置ルール | 分類間の移動で、移動先の先頭か末尾かを決めるルール(今日・完了=先頭、明日・今週=末尾) |
| 入力開始エリア | スマホで、各分類の末尾にある、タップすると入力を始められる空白のエリア |
| クイック追加 | 入力開始エリアから、連続してタスクを追加する操作 |
| 操作バー | スマホの入力中に、キーボードの上に出るバー(「×」と「新規追加」) |
| 通知メッセージ | 画面下に出る、短いメッセージ(移動後、エラー用) |
| アクセントカラー | 操作ボタンなどに使う、緑系の色 |
